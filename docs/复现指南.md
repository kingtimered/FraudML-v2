# 复现指南

在FraudML-v2目录执行。原代码与数据使用相邻目录的只读输入，不复制大数据，不改动原项目。新版为独立Python包，不需要启动原服务。

## 环境

本次使用Python 3.12.14。requirements-runtime.txt记录实际使用的主要依赖，run.json保存逐次运行的具体版本。原记录环境未锁定所有依赖，因此旧版重跑应同时展示归档值与当前值，不保证逐位一致。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-runtime.txt
```

macOS上的LightGBM需要OpenMP。scripts/python_env.py在子进程启动时使用scikit-learn安装包携带的libomp（存在时），同时设置两线程和本地matplotlib缓存；本次环境已验证可运行。其他平台按自身LightGBM依赖安装要求配置。运行命令统一经该启动器进入。

## 正确性与数据检查

```bash
python3 scripts/validate_plan.py
.venv/bin/python scripts/python_env.py -m pytest -q
```

10项测试覆盖逐值规范化、严格历史、同时间戳、24小时边界、任意分块、训练期截尾、队列容量、配对重采样权重和模型保存加载一致性。合成数据可另行检查整条流程：

```bash
.venv/bin/python scripts/python_env.py scripts/run_study.py --run-id my_smoke --smoke
.venv/bin/python scripts/python_env.py scripts/analyze_results.py --run-id my_smoke --smoke-draws 30
.venv/bin/python scripts/python_env.py scripts/verify_study.py --run-id my_smoke
```

合成结果不能写入作业模型结论。各命令拒绝覆盖已存在的相应产物，重跑使用新run_id。

## 完整固定实验

```bash
.venv/bin/python scripts/python_env.py scripts/run_study.py --run-id my_study
.venv/bin/python scripts/python_env.py scripts/analyze_results.py --run-id my_study
.venv/bin/python scripts/python_env.py scripts/verify_study.py --run-id my_study
.venv/bin/python scripts/python_env.py scripts/plot_results.py --run-id my_study
.venv/bin/python scripts/python_env.py scripts/diagnose_lr.py --run-id my_study
```

依次训练21个固定模型、对保存的分数做1000次配对3日块重采样、独立复算指标与队列、生成3组可导出的PNG/PDF图。最后的diagnose_lr.py只读取已保存模型与最高分交易，分解线性得分并检查重构一致性；它是事后描述诊断，不增加训练或调参，不能把贡献解释为因果效应。若初始LR未收敛，该快照的全部三个LR统一提高到3000迭代重试一次，最多额外9次拟合。训练和重采样的运行耗时见各run.json与paired_intervals.json。

configs/study_plan.json中的planned与training_executed=false是**冻结方案时的状态**；为保持协议与审计哈希，不随运行改写。实际执行状态只以results/<run_id>/run.json和verification.json为准。分析、绘图和核验代码各自记录实际代码哈希；训练时的source_hashes只描述该次训练启动时的文件内容。

## 旧版重跑

```bash
.venv/bin/python scripts/python_env.py scripts/replay_legacy.py --run-id my_legacy
.venv/bin/python scripts/python_env.py scripts/verify_legacy_alignment.py --run-id my_study --legacy-run-id my_legacy
```

直接导入未修改的原fraudml模块，训练旧LR、旧LightGBM与旧历史版共3个模型，在原验证和测试期评分。保留原概率排序并额外保存margin诊断。LightGBM仅将线程数设为2以限制资源；记录当前环境与原环境差异。归档JSON始终保留，archived_comparison.json列出重跑差异。

第二条命令核对当前环境下新版共同基线与原代码重跑的逐笔margin、概率和交易标签；它不保证历史环境的精确复现。所有步骤完成后，可另存一个不含原始交易、逐笔分数或模型的摘要：

```bash
.venv/bin/python scripts/python_env.py scripts/export_summary.py --run-id my_study --legacy-run-id my_legacy --out evidence/my_summary.json
```

本次已保存evidence/executed_summary.json。若已有LR贡献文件而仅需补充日期集中度，可用diagnose_lr.py的--timing-only参数生成独立sidecar；各输出仍拒绝覆盖。

## 产物

results/<run_id>/下的models与predictions包含逐笔分数及模型，默认不纳入Git。metrics.json、daily_metrics.csv、weekly_metrics.csv、review_queues.parquet对应同一排序。主表primary_results.csv使用全期0.5%预算；probability_diagnostics.json和diagnostics.json保留数值与收敛信息，警告保存在diagnostics.json的warnings中。运行耗时保存在run.json、diagnostics.json；不创建没有内容的warnings.log或runtime.json。

analyze_results.py生成paired_intervals.json和新版实验结果.md。verify_study.py另外按pandas稳定排序从保存分数复算，检查交易标签、每期候选对齐、审核容量和名单。它不重新训练模型，也不证明统计区间覆盖率或未来泛化。

不运行大范围调参，不因测试结果增加候选，不将单日差异写成长期规律。HTTP服务、概率校准、identity建模与旧报告附录恢复不在本次完整实验的完成范围。

## 后续质量审计与稳健性分析

本次补充配置是configs/supplement_plan.json，明确标注post_hoc_sensitivity_no_tuning。主实验和原3日块区间不覆盖。实际产物位于evidence/supplement_20261121_01，其中包括完整394列三分区审计、1/3/7日块比较、332个连续1/2/7日省略窗、独立环境记录与核验。复算时使用新的输出目录：

```bash
.venv/bin/python scripts/python_env.py scripts/audit_quality.py --out evidence/my_supplement/quality_audit.json
.venv/bin/python scripts/python_env.py scripts/analyze_sensitivity.py --out-dir evidence/my_supplement
```

两条命令可独立运行。第二条需要study_20261121_01的原逐笔分数；若更换主运行编号，先在独立副本的补充配置中明确记录，不改写本次归档配置。省略只作用于评价行，不重建历史或重新拟合；遍历所有连续日窗，不据结果删除困难日期。

独立环境检查可以复算如下。安装可能需要联网下载，安装到项目内新目录；主要依赖沿用requirements-runtime.txt，实际完整依赖另由pip freeze保存。

```bash
python3 -m venv results/my_clean_environment/.venv
results/my_clean_environment/.venv/bin/python -m pip install -r requirements-runtime.txt
.venv/bin/python scripts/check_clean_environment.py --python results/my_clean_environment/.venv/bin/python --out-dir evidence/my_supplement --smoke-run-id my_clean_smoke
.venv/bin/python scripts/verify_supplement.py --evidence-dir evidence/my_supplement
.venv/bin/python scripts/python_env.py scripts/build_report.py --evidence-dir evidence/my_supplement --report-path docs/my_recomputed_report.md
```

check_clean_environment.py拒绝继承系统site-packages的环境，记录pip check、10项测试与合成训练/分析/核验。本次实际使用Python3.12.14、macOS arm64，独立环境完整依赖见requirements-clean-macos-arm64.txt；没有在独立环境再次执行全量真实数据拟合。

verify_supplement.py使用按行分块读取的独立方法复算1182组字段×分区缺失计数、126个重点字段分位数，并核对全部日窗数量、原区间和来源哈希。它不证明区间覆盖率或因果解释。build_report.py只在补充核验通过后生成报告和图表，默认拒绝覆盖已有产物。
