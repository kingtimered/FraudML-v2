# 报告与交付清单

版本：2026-11-21.plan2。以下为冻结的实验交付要求；实际状态另见现有证据与缺口及各运行目录。

## 报告结构

1. 问题：给定预算下的排序稳定性与两类增量改进。
2. 数据：交易数与时间长度分别讨论，匿名字段、标签时点和代理实体限制。
3. 方法：固定七配置、两个28天开发期、原训练快照的验证/测试回顾性比较。
4. 基础结果：相同审核比例的期级指标、预算曲线与跨期变化。
5. LR修复：截尾与正则化、收敛、margin/概率诊断，含负向结果。
6. 历史消融：H0-H3与配对差异，不仅比较AP。
7. 每日补充：日批处理、同总容量全期对照、周级汇总与边界敏感性。
8. 正确性与局限：评分/队列一致性、日期少及已有测试暴露。

identity和动态资源分配不列入核心结果。解释性图优先恢复旧证据，缺原文件时不能直接当作新结果。

## 运行目录

results/<run_id>/中保存：

- run.json：状态、时间、命令、协议/数据/代码哈希、完整参数、环境和线程。
- splits.json：精确时间边界、样本/标签/日桶数、ID清单哈希。
- predictions.parquet：交易标识、时间、期别、配置、seed、label、margin/概率/排序分数，保存于本地。
- metrics.json与daily_metrics.csv：实际容量、命中、标签分母、指标、场景。
- paired_intervals.json：对照、重采样次数/种子/块长、有效次数和差异区间。
- diagnostics.json：收敛、警告、异常、截尾范围与训练评分耗时；run.json记录总耗时。不另建空warnings.log或runtime.json。
- 图表及对应生成命令，实际manifest清单。

不同预算复用相同分数；缺少步骤时记NA，不提前创建“已完成”的空结果。输入数据、逐笔分数、模型不提交到公开仓库；可分享小型汇总和复现代码。
