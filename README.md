## 本次修订

主线收缩为三个问题：预算变化下的排序与时间稳定性、LR 数值处理修复、历史特征的增量价值。每日审核是补充的日批处理评价场景，不声称解决跨日期资源优化。identity、概率校准、标签延迟模拟、GraphSAGE 和生产部署暂缓。

- 用两个 28 天且评价期不重叠的开发窗口，替换三个 14 天窗口。
- 核心不设置无依据的 7 天标签延迟，明确历史标签可用是假设。
- 主要比较全期相同审核比例下的排序；0.5% 是预先规定的实验参考点，不是最佳业务预算。
- 每日预算 8/16/32 是敏感性场景，不再把 16 当作已知真实容量。
- 固定 7 个模型配置、三个训练快照；不做大范围搜索，不在测试后选赢家。
- 输出命中差异和配对区间；承认日期少、日期相关及已有测试集被查看的限制。
- 修正“首尾日必定不完整”的表述。只识别由切分造成的日桶缺失，不因末笔交易没有落在午夜就删日。

## 自检与数据审计

从本目录执行。静态检查只依赖 Python 标准库；数据审计额外需要 pandas。

```bash
python3 scripts/validate_plan.py
python3 scripts/audit_data.py --out evidence/data_audit.json
```

审计脚本不训练模型，不改动数据；默认拒绝覆盖已有结果，确需重跑使用 `--overwrite`。审计成功只证明数据规模、划分和容量可行，不证明模型改善或未来稳定性。

`evidence/legacy_metrics/`是四份旧指标的原样快照；`evidence/source_manifest.json`保存来源路径与SHA-256。results下每次运行使用唯一run_id并拒绝覆盖。模型和逐笔分数保存在本地，默认不纳入Git。

configs/study_plan.json中的planned与training_executed=false表示冻结方案时的状态，为保持审计哈希不随执行改写；实际状态看对应run.json与verification.json。警告和耗时分别保存于diagnostics.json、run.json，不以空占位文件代替运行记录。

数据不足以支持的长期、实时和财务收益结论保留为局限，不用重复抽样、增加模型或移动切点来弥补。

本地提交包：deliverables/FraudML-v2-coursework-20261121.zip。包含正式Markdown报告、研究图、代码、聚合证据与必要旧来源，不含原始交易、逐笔分数、模型或运行环境。包内逐文件哈希可核验；完整真实数据重训仍需原始数据。尚未向课程平台提交。生成方法见[复现指南](docs/复现指南.md)。
